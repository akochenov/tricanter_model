# Модель трикантера, MATLAB/Simulink

Динамическая компартментная модель трёхфазной декантерной центрифуги.
Перенос рабочей питон-модели в Simulink.

## Быстрый старт (на случай, если slx поломался)

```matlab
cd matlab
build_data_dictionary        % собирает tricanter_data.sldd
build_model                  % собирает tricanter_top.slx
```

Затем `Ctrl+D`, потом Run. Ожидается 1500 шагов и всё по нулям —
физика пока в заглушках, это правильно. Важно - это соберет старую версию, 
надо будет править/просить кого то чтоб обновил

Проверка каркаса:

```matlab
cd ../tests
test_A_geometry
```

Геометрия готова, поэтому её девять чисел должны сойтись с эталоном.

## Что где

```
matlab/     функции модели и два сборочных скрипта
tests/      тесты и загрузчики эталонов
ref_dyn/    эталоны из питона, 30 CSV
python/     скрипт выгрузки эталонов
```

`build_data_dictionary.m` и `build_model.m` пересоздают словарь и модель
с нуля. Ручные правки в них теряются — но зато их не надо набирать
руками в Type Editor.

## Как работать

Девяносто процентов времени Simulink не нужен. Открываете свой `.m`,
пишете тело, проверяете против CSV обычным вызовом функции:

```matlab
[x, w] = tric_psd(3.0e-6, 2.0, false);
p = ref_load('psd_drops_3ph');
chk(x, p.x); chk(w, p.w);
```

Цикл секундный. Модель — способ увидеть результат целиком,
а не среда разработки.

Зачем сделано так — **ORIENTATION.md**, читать первым.
Где мы сейчас и что дальше — **NEXT.md**.
Сигнатуры и структуры шин — **CONTRACT.md**.
Тесты по участникам — **TESTING.md**.
Текущее состояние — команда `project_status` в MATLAB.

## Правила

1. `.slx` и `.sldd` открывает только A. Git не сливает бинарные файлы.
2. Параметры не трогать до недели 3 — эталоны к ним привязаны.
3. Каждая функция сверяется и на `step1`, и на `steady`. Первый ловит
   опечатки, второй — недописанную физику.

## Раскладка

| | файлы |
|---|---|
| A | каркас, `tric_dims`, `tric_geometry`, `tric_rhs`, сборочные скрипты, сценарии |
| B | `tric_psd`, `tric_grade`, `tric_settle_dyn`, оба каскада |
| C | `tric_cake_geom`, `tric_cake_balance` |
| D | `tric_outputs`, `tric_limits`, верификация, идентификация `u_conv` |

## Порядок оживления

Модель работает при любой комбинации готовности. Осмысленные числа
появляются так:

`tric_psd` → реальные классы частиц
`tric_cake_geom` → `Rtr` зависит от массы
`tric_grade` + `tric_settle_dyn` + `tric_cascade_solids` → появляется захват, `E_s` перестаёт быть нулём
`tric_cake_balance` → кек растёт, замыкается обратная связь
`tric_cascade_drops` → появляется обводнённость нефти
`tric_outputs` → выходы наполняются

Критический путь — B и C.

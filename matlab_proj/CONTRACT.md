# Контракт: кто что пишет и с какими сигнатурами

Динамический вариант (§7.2 постановки). Заменяет старую квазистатическую
редакцию — если у вас в руках документ, где упоминается `tric_settle`
с шестью аргументами и без `dt`, он недействителен.

## Правило первое

**`.slx` и `.sldd` открывает только A.** Они бинарные, git их не сливает.
Понадобилось новое поле в шине — пишете A, он добавляет и пушит.
Нарушение правила означает, что кто-то потеряет работу целиком.

## Правило второе

Параметры не трогать до недели 3. Все CSV-эталоны привязаны к
дефолтному `Params()` из питона. Поменяли `u_conv` или `phi_sed` —
эталоны недействительны, нужен перезапуск `dump_reference_dyn.py`.

---

## Состояния

Три штуки, все дискретные, шаг `Ts = 1.0 c`.

| состояние | размер | блок | смысл |
|---|---|---|---|
| `m` | 25×1 | Discrete-Time Integrator | масса кека по ячейкам |
| `phi_s` | 25×40 | Unit Delay | твёрдое в ячейках по классам |
| `phi_w` | 25×40 | Unit Delay | капли воды в ячейках по классам |

`m` накапливается: `m(k+1) = m(k) + Ts·dm`. Нижняя отсечка на нуле обязательна.

`phi` не накапливается. Обновление точной экспонентой внутри функции:
`phi_next = star + (phi_prev − star)·exp(−dt/tau)`. Поэтому Unit Delay,
а не Integrator.

`r_i` — **не состояние.** Алгебраическая величина из баланса давлений,
пересчитывается каждый шаг в `tric_geometry`.

## Размерности

`n = 25` ячеек, `J = 40` классов частиц. Заданы литералами в `tric_dims.m` —
иначе codegen не выведет фиксированные размеры и Simulink откажется
компилировать блок.

## Сигнатуры

### A — каркас

```matlab
[n, J] = tric_dims()
geo    = tric_geometry(u, pc)                                  ГОТОВО
[dm, phi_s_next, phi_w_next, y] = tric_rhs(m, phi_s, phi_w, u, pc, dt)
```

`tric_rhs` — оркестратор, физики в нём нет. Порядок вызовов: геометрия,
PSD, кек, каскады, баланс, выходы.

### B — дисперсная фаза

```matlab
[x, w]                       = tric_psd(d50, b, rrsb)
T_mat                        = tric_grade(x, k0, tau, pref, phi_cells, phi_ref)
[cap, phi_next]              = tric_settle_dyn(phi0, w, T_mat, phi_prev, tau, dt)
[cap_s, phi_s_next, phi_s_out] = tric_cascade_solids(phi_s, Rtr, geo, u, pc, dt)
[phi_w_next, phi_w_out]        = tric_cascade_drops(phi_w, geo, u, pc, dt)
```

**Две ловушки.**

`tric_grade` принимает `tau`, уже домноженный на `f_clar`.
`tric_settle_dyn` принимает голый `tau`. В CSV записан голый.

В префакторе `pref_s` стоит `Rd`, а в `tau_s` — `Rtr`. Gleiss в печатных
формулах поставил `Rtr` в оба места и тем разорвал единственную обратную
связь модели, из-за чего `U` уходит в единицу. У нас должно быть по-разному.

Несущая фаза для твёрдого — вода, `eta_w`. Для капель — нефть, `eta_o`.
Перепутать значит ошибиться в тридцать раз.

### C — кек

```matlab
[Rtr, dH] = tric_cake_geom(m, geo, pc)
[dm, tr]  = tric_cake_balance(Rtr, cap_s, geo, pc)
```

`tric_cake_geom`: толщина слоя из объёма кольца, `Rtr` от `Rd` внутрь.
Отсечка `sqrt(max(..., r_i^2))` обязательна, иначе при большой массе
получится корень из отрицательного.

`tric_cake_balance`: приход `cap_s`, унос шнеком `Kscr·Δn·m`, сдвиг
`[tr(2:end); 0] - tr`. Знак сдвига — самая частая ошибка; проверяется тем,
что в установившемся режиме `dm ≈ 0`.

### D — выходы и пределы

```matlab
y     = tric_outputs(m, Rtr, dH, cap_s, phi_s, phi_w, phi_s_out, phi_w_out, tr, geo, u, pc)
flags = tric_limits(geo, u, pc)
```

## Шины

Порядок элементов внутри шины обязан совпадать с порядком полей
в структуре, которую собирает код. Расхождение даёт ошибку компиляции
вида «assignment writes ... into field». Все шины собираются скриптом
`build_data_dictionary.m` — руками в Type Editor больше не нужно.

**BusTricInputs** (12): eta_o, d50, x50, eps_s, eps_wd, eps_wf, eps_o,
Rw, Ro, Q, dn, C

`eta_o` лежит во входах, а не в параметрах: сценарий 13.5 меняет её
при охлаждении сырья.

**BusTricParams** (17): Rd, Wsc, Lpond, alpha, Lsep, rho_s, rho_w, rho_o,
eta_w, mu_s, phi_sed, phi_max, phi_ref, u_conv, bs, bw, rrsb `boolean`

**BusTricGeo** (10): omega, beta, Lax, L_cone, f_clar, u_ax, r_i, Qo, Qw,
has_oil `boolean`

**BusTricOut** — вложенная, четыре ветки строго в этом порядке:

| ветка | элементы |
|---|---|
| `cake` | Rtr(25), dH(25), m_cake(25), m_cake_tot, tau_s(25) |
| `streams` | mdot_oil, mdot_water, mdot_cake, x_w_in_oil, x_o_in_water, x_s_in_cake |
| `quality` | U, E_s, E_w, phi_s_out, phi_w_out, phi_s_prof(25), phi_w_prof(25), E_s_i(25), tau_c |
| `flags` | bal_resid, M_scroll, f_oil_collapse, f_water_collapse, f_overload, f_overfill |

Четыре последних флага — `boolean`. `bal_resid` и `M_scroll` — `double`.

## Три уровня эффективности, которые легко перепутать

`T(i,j)` — вероятность частице класса `j` осесть в ячейке `i`. Не кумулятивна.

`E_s_i` — свёртка `T` по классам: доля осевшего в ячейке `i` от того,
что в неё вошло. **Не кумулятивна.**

`E_s` — сквозная эффективность машины. Кумулятивна.

На защите это спросят.
